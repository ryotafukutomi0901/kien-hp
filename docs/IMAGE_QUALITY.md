# 画像の画質: 原因と改善案

2026-10-03 作成。数字は実測（元画像は `public/images/` のファイル、表示サイズは1440px幅のブラウザで測定）。**確かめていないことは「未確認」と書く。**

## 結論

画質が悪い原因は、**元の写真が小さすぎること**（幅92〜330px）。それを1.4〜5.7倍に引き伸ばして表示している（Retinaの画面では2.8〜11.4倍）。
サイトのコードや画像の圧縮設定が原因ではない。コードを直しても画質は上がらない。**写真そのものを高解像度のものに替えるしかない。**

## 1. なぜ小さいのか

仮画像は、参考モックに添付された素材シート（`reference/asset-sheet.png`、1536×1024）から切り出したもの。
シートには写真が小さなサムネイルとして並んでいて、1枚あたり幅200px前後しかない。切り出してもその大きさにしかならない（`scripts/extract-placeholders.py`）。
さらに、シートの画像自体が画像生成AIの出力で、200pxの中に写っている細部も多くない。

## 3. 原因の切り分け（確認したこと）

| 疑った原因 | 結果 |
|---|---|
| Next.jsの画像最適化が劣化させている | **違う。** 元画像より大きくしない設定になっていることを確認した（330px幅の画像に幅640〜3840を要求しても、返るのは330px幅のまま）。圧縮の品質はquality 75で、元画像が高解像度なら問題ない |
| CSSで画像をぼかしている | **違う。** 意図的にぼかしているのは「私たちのこと」の背景だけ |
| JPEGの再圧縮で劣化した | **わずかにある。** 素材シートからの切り出しをJPEG（品質90）で保存し、さらにNext.jsが配信時に再圧縮している。ただし影響は小さく、主因ではない |
| 葉っぱの切り抜きが荒い | **ある。** 白い背景をしきい値で抜いた簡易処理で、縁に白いにじみが出る。元画像が小さい（74〜162px）ことも重なっている |

## 4. もう1つの問題: 写真の人物は実在のスタッフではない

仮画像に写っている人物は、参考モックを作った画像生成AIが描いた架空の人物。会社の実際のスタッフ・利用者ではない。
介護事業者のサイトで、実在しない人物をスタッフや利用者のように見せるのは、信頼を損なう。**高解像度にしただけでは解決しない。本番では実際の写真にするのが望ましい。**

## 5. 改善案

### 必要な写真のサイズ（1440px幅の画面で、Retinaでもぼけないための目安）

| 場所 | 表示サイズ | 必要な元画像（幅×高さ以上） | 構図の注意 |
|---|---|---|---|
| ヒーロー | 1440×684 | **3000×1400** | 横長。富士山は右寄り。文字を載せる左側は空など無地に近い構図 |
| 私たちのこと（楕円） | 612×344 | 1300×730 | 横長。山頂が楕円の上3分の1に来る構図 |
| 私たちのこと（背景） | 1440×368 | ヒーローの写真を流用（別撮り不要） | ぼかして使うので細部は不要 |
| サービス3枚 | 378×110（スマホは約343×120） | **各 1200×800（3:2）** | 人物の顔や手元を上寄りに。上下が切られても成立する構図 |
| 会社行事 | 262×126 | 各 800×600 | 行事のスナップ写真で足りる |
| お知らせ | 371×143 | 800×320 | 装飾なので風景でよい |
| 採用情報・スタッフの一日 | 214×178・237×178 | 各 600×450 | スタッフの働く姿 |
| 最終CTA | 432×144 | 1000×330（3:1） | 富士山と街並みの横長 |
| 葉っぱ6種 | 128〜314px | **PNGは幅600px以上、またはSVG** | 透過は専用の切り抜きで |
| ロゴ | 72×85 | SVGの原本 | 下記参照 |

### 入手方法の比較

| 方法 | 向いている場所 | 長所 | 注意点 |
|---|---|---|---|
| **A. 実際に撮影する（推奨）** | スタッフ・事業所・利用風景 | 実在の写真で信頼できる。スマートフォン（1200万画素＝4032×3024）で上の表をすべて満たす | 利用者の顔が写る写真は、事前に書面での同意が必要。スタッフにも掲載の同意を取る。晴れた日の自然光で、横向きに撮る |
| B. クライアントが持つ写真 | 会社行事 | 旧サイトの会社行事の写真は実在の写真 | 旧サイトの写真の実際の大きさは**未確認**（ダウンロードを承認いただいていない。ファイルサイズは1枚125〜509KB）。Jimdoに載せるときに縮小されている可能性があるので、**スマートフォンに残っている元の写真を直接もらう**のが確実 |
| C. 有料の写真素材（PIXTA・Adobe Stock等） | ヒーロー・最終CTA・私たちのこと（富士山と街並み） | 高解像度で品質が安定。ライセンスが明確 | 人物写真は「実在のスタッフではない」問題が残るので風景だけにする。ライセンス費用がかかる |
| D. AIで高解像度に生成する | 風景のみ | 費用と手間が小さい | 出力の解像度と費用は、利用できる生成ツール（Higgsfield）で**未確認**。実在しない街並みになるので「富士市の風景」と書けない。人物は上記の理由で使わない |
| E. いまの小さな写真をAIで拡大する | 非推奨 | — | AIの拡大は、失われた細部を**作り出して補う**処理で、元の情報は戻らない。幅186pxの写真の拡大では、絵の具で塗ったような質感になりやすく、人物の顔は別人のようになることがある。いまの写真は架空の人物なので、拡大してもスタッフ写真としては使えない |

**推奨の組み合わせ**: 人物と事業所はA（撮影）、会社行事はB（元の写真を直接もらう）、ヒーロー・最終CTA・私たちのことの富士山と街並みはC（風景素材）またはA（クライアントや弊社が撮影した富士山）。Eは使わない。

### 撮影する場合の撮影リスト

1. 事業所の外観（看板が見える）と入口、事務所の中（明るい時間帯）
2. ケアマネジャーの相談風景、ヘルパーが利用者宅で支援する場面（同意を得た方のみ。手元・後ろ姿でもよい）
3. 家事支援（お掃除・育児・お食事）の場面
4. スタッフの集合写真（笑顔、屋外）
5. 富士山（晴れた日、街並みを入れた横長）
6. すべて**横向き・撮影後にトリミングしない**（切り抜きはサイトで行う）

### 写真が届くまでにできること

- 仮画像のまま公開しない（`docs/CONTENT_SOURCE.md` の「納品前に必ず解消する」に追加）。確認用の画面共有であれば、現状のまま見せてよい
- 本番素材は**同じファイル名で `public/images/` に上書き**すれば反映される（`data/sections/*.ts` の `position` は被写体に合わせて調整）
- 配信形式は、写真が届いたら `next.config.ts` の `images.formats` にAVIF・WebPを指定する（現在は未設定。元画像が小さい今は効果がない）

### ロゴ

- 提供されたロゴは `reference/logo/` に保存。`scripts/make-logo-assets.py` でヘッダー用（カラー）・フッター用（白）・ファビコン・SNS共有画像を作った。表示サイズ（72px幅）に対して元の絵柄は268px幅あり、ぼけない
- 縦組みのカラー版（`喜援ロゴ.png`）は、透過PNGの形式だが**背景は不透明な白**だった。今回、白を透明にして使っている。デザイナーから**SVGまたはAI形式の原本**をもらえるとより確実（印刷物・大きな看板にも使える）
